From an r24 build to repeatable checks

November 13–21, 2026

How the Windows build, corrected test fixtures and Linux BSPC fix were qualified.

Freeze the build inputs

The Windows r24 run used a frozen source tree and fresh CMake graphs for Debug and Release. Windows full-core and idlegacy targets were built first. The headless suite then selected the same 87 cases in each configuration from 95 registered cases. It was a test of the selected build and fixtures.

Fix the harness and rerun the whole cohort

The first suites each returned 76 passes and 11 failures. Ten failing checks needed files that were absent from the isolated tree. The staging check also needed to use the configurations actually declared by the generated solution. The corrected fixture added 21 pinned files and used the original r24 products. All 11 failures passed in the focused replay. A fresh run of the full selected suite then passed 87 of 87 in Debug and 87 of 87 in Release, with zero selected cases skipped.

Compare runtime modes

Separate dedicated runs loaded the private qagame program in interpreted and compiled QVM modes in both configurations. A later headless comparison also passed four native-versus-JIT qagame cases. The isolated client comparison found exact matches on four settled UI menu image pairs. Four cgame comparisons held the reported viewpoint and showed small raster differences. The largest was 497 of 786,432 pixels, with a maximum channel difference of 2 out of 255.

Carry the warning fixes forward

The November 21 Linux BSPC work fixed filename storage. It rejects a whole path of 1,024 bytes or more before opening the file and preserves the terminating byte for shorter names. Both configurations compiled and linked without reported diagnostics, matched their prior public symbol inventories and verified 38 exported files. The focused run leaves formatted logging, the full Linux graph, deployment and broader runtime coverage open.
